## 2026-11-28 iPhone 10분 실행과 발열 대응

- iPhone 18 Pro 10분 자동 플레이(충전 중, 개발 서명 앱): 35,861 프레임, 평균 16.68 ms(60.0 FPS), 최대 40.63 ms,
  250 ms 넘는 프레임 0회. 열 상태 정상 336초 → 약간 높음 180초 → 높음 81초. 자세한 값은 PERFORMANCE_REPORT.
- 같은 실행에서 `--exit-after 600` 뒤에도 앱이 끝나지 않는 것을 발견했다(winit이 iOS에서 종료 요청을 무시). 고침(이슈 #38).
- 발열 대응(열 상태 "높음" 이상에서 30 FPS)과 `hot_target_fps` 설정을 추가했다. 테스트 3개 추가(목표 계산,
  "높음" 판정, 설정 범위). 전체 190개 통과, 1개는 진단용으로 원래 제외. fmt, clippy(macOS·iOS 대상), macOS 릴리스
  빌드 통과. macOS 화면 밖 자동 플레이 8초 정상 종료.
- 새 개발 빌드를 기기에 설치했으나, 15분 확인 실행은 기기가 잠겨 40분 동안 시작하지 못했다. 발열 대응과 iOS 종료
  수정은 실기기에서 확인하지 않았다.
- iOS 종료 수정은 iPhone 18 Pro 시뮬레이터에서 확인했다. 처음 고친 방식(종료 요청 0.5초 뒤 다음 프레임에서 끝내기)은
  앱이 120초 넘게 남아 실패했다. 종료를 요청한 뒤 Bevy가 프레임을 더 돌리지 않기 때문이다. 같은 프레임의 `Last`에서
  세션을 닫은 뒤 끝내도록 바꾸자 `--exit-after 20`이 실행 22초 만에 끝났다. 파일 DB로 `--exit-after 15` 실행:
  `simctl launch --console` 종료 코드 0(17초), 성능·기기 상태 줄 출력, 세션 `ended_at` 기록·잔액 54·게임 4판 저장.
  다시 돌린 검사: 테스트 190개 통과, clippy(macOS·iOS), macOS 릴리스 빌드, macOS 자동 플레이 정상 종료.
  고친 개발 빌드를 iPhone에 다시 설치했다.
- 시뮬레이터 열 상태는 실행 내내 "정상"이었다. 시뮬레이터에서는 "높음"을 만들 수 없다.
- iPhone 발열 대응 확인(사용자가 잠금 해제, `--exit-after 900`): 약 488초에 열 상태 "높음" → "목표 프레임률 60 → 30 FPS"
  기록, 이후 1분마다 1,800프레임(30.0 FPS). 그 뒤 약 5분 동안 "높음"이 유지되어 60 FPS 복귀는 보지 못했다.
  배터리로 돈 약 10분 동안 95% → 90%, 그 뒤 전원 연결. 약 13분(06:47:44)에 앱이 SIGKILL로 끝나 `--exit-after`
  종료는 실기기에서 확인하지 못했다. 기기에 크래시·jetsam 보고서는 없다(이슈 #39). 자세한 값은 PERFORMANCE_REPORT.

## 2026-11-27 macOS 실제 입력 조작

화면 제어 도구로 서명된 `dist/FruitStar3D.app`(`--db :memory:`)에 실제 macOS 키보드·마우스 이벤트를 보냈다.

| 조작 | 결과 |
|---|---|
| 메뉴 버튼 마우스 클릭 | 프리 플레이 진입 |
| 창 최소화(포커스 상실) | 자동 일시정지, 계속하기 클릭으로 복귀 |
| 키보드 B · Space · 1 · 2 · 3 | 크레딧 50→47, 포도 당첨 +8 → 55 |
| 3D 부품 클릭: MAX BET, 레버 손잡이, 정지 버튼 3개 | 크레딧 60, "포도 당첨! +8" 배너와 당첨 줄 표시 |
| 빈 곳 드래그 · 스크롤 | 시점 회전과 확대가 반영됨 |
| V · Esc | 시점 전환, 일시정지 화면 열기·닫기 |

| M | HUD에 "음소거" 표시, 다시 누르면 해제 |
| F | 전체 화면 진입과 해제. 단, 진입 애니메이션 직후(약 1.5초 뒤)에 누른 F는 한 번 무시되었고, 다시 누르자 창으로 돌아왔다 |

창이 포커스 없이 열리면 플레이 진입과 함께 자동 일시정지가 걸리고, 계속하기를 누르면 이어진다.
실제 트랙패드 핀치는 화면 제어 도구로 보낼 수 없어 손으로 하지 못했다. 대신 Bevy `PinchGesture` 입력을 넣어 확대·축소 명령이 나오고 일시정지 중에는 무시되는지 헤드리스 테스트 2개로 확인했다. 소리는 청취하지 않았다.

## 2026-11-27 "소리가 들리지 않음" 조사

- 게임 쪽 출력은 정상이다. 시뮬레이터 자동 플레이 중 macOS `coreaudiod`에 iOS 시뮬레이터 오디오 출력 활성 표시가
  생겼고, 앱의 저장된 음향 설정도 기본값(음소거 꺼짐, 전체 80%)이었다. 맥 앱의 저장 설정도 음소거 꺼짐이다.
- 이 Mac의 시스템 출력은 "외장 헤드폰"이며 출력 볼륨 0, 음소거 상태였다. 맥과 시뮬레이터에서 소리가 들리지 않은 원인이다.
  시스템 설정은 바꾸지 않았다.
- iPhone: cpal(0.17)은 오디오 세션 카테고리를 정하지 않아 iOS 기본값(SoloAmbient)을 쓴다. 이 카테고리는 무음 모드에서
  소리를 내지 않는다. 앱은 무음 모드를 알 수 없어서, 터치 기기의 일시정지 화면 음향 항목에 무음 모드·기기 볼륨 안내를
  추가했다. 무음 모드에서도 소리를 내려면 오디오 세션을 바꾸는 unsafe 코드가 필요해 하지 않았다(프로젝트 규칙).
- 테스트 178개 통과. macOS 번들과 시뮬레이터·실기기 앱을 다시 만들어 설치했다.
- 사용자가 iPhone에서 무음 모드를 끄자 게임 소리가 나는 것을 직접 확인했다(원인: 무음 모드). 음색·음량 균형에 대한
  청취 평가는 아직 받지 않았다.

## 2026-11-27 첫 실행 멈춤 수정 (렌더 예열)

- 원인 확인: Bevy 0.20은 macOS·iOS에서 렌더 파이프라인을 프레임 안에서 동기식으로 만든다. 장면이 로딩이 끝난 뒤
  생성되어, 메시 파이프라인 13개가 메뉴·플레이 첫 프레임에서 컴파일됐다. 셰이더 캐시가 빈 실행에서는 플레이 시작 후
  1.1 · 3.6 · 3.1초 멈춤이 기록됐다.
- 수정: 로딩 상태에서 장면을 만들고 숨은 부품(당첨 라인, 옆자리 게임기)과 메달 하나를 불투명한 로딩 화면 뒤에서
  그린다. 렌더 월드가 보고하는 대기 파이프라인이 0이 되고 수가 4프레임 그대로이면 메뉴로 넘어간다(최대 30초).
- 결과: 예열에 약 300 ms·7프레임이 걸리고 파이프라인 67개가 모두 로딩 중에 만들어졌다. 이후 12초 자동 플레이에서
  새 파이프라인은 생기지 않았고 최대 프레임은 16.2 ms였다. 예열 뒤 당첨 라인은 다시 숨고 당첨 줄만 표시됐다.
- 빈 캐시 대용 재현: 시스템 공용 Metal 캐시는 지우지 않았고, 캐시 관련 환경 변수(`MTL_SHADER_CACHE_DISABLE` 등)는
  효과가 없었다. 대신 `MTL_SHADER_VALIDATION=1`로 셰이더를 계측 컴파일하게 해 컴파일을 크게 느리게 만들었다. 예열이
  15,330 ms·7프레임 걸렸고, 이어진 약 9초 플레이에서 긴 프레임 경고는 없었다(검증 계층 부하로 평균 38.6 ms, 최대
  135.5 ms). 느린 컴파일이 로딩 화면 안에서만 일어남을 확인했다. 그동안 로딩 화면은 갱신되지 않는다. 실제 빈 캐시
  상태 자체는 재현하지 않았다.
- 자동 실행(`--auto-play`, `--offscreen`)은 처음부터 창 포커스가 없어 예열로 로딩이 길어지자 플레이 직후 자동
  일시정지가 걸렸다. 자동 실행에서는 포커스 상실 일시정지를 끄도록 했다(테스트 2개).
- 형식·Clippy 통과, nextest **178개 통과**(핀치 테스트 2개 포함), 진단용 1개 건너뜀. macOS 번들, iPhone 시뮬레이터(메뉴·프리 플레이 진입
  확인), iPhone 실기기 번들을 다시 만들었다. 실기기는 잠겨 있어 실행하지 못했다.

- 자동 플레이의 네 연속 사진에서 타공 끝판과 인쇄 띠가 함께 회전하고 지지대가 제자리를 지키는 모습을 확인했다. [정면 플레이](screenshots/reel_front.png) · [내부 관찰 확대](screenshots/reel_drum.png)
- 메모리 저장소로 실행한 직접 조작용 번들이 macOS 전면에 창 한 개를 열었다. 실제 창에서 캡처한 3024×1718 화면으로 내부 관찰 확대 시점을 확인했다.

## 2026-11-26 UI 개편 검증

- 형식과 Clippy 검사 통과. 워크스페이스 nextest **159개 통과, 진단용 1개 건너뜀**. 베팅 1장을 건 뒤 회전·지급 중에도 같은 수량을 표시하는 회귀 테스트를 추가했다.
- 임시 검증 실행 파일이 실제 Metal 화면에 Bevy 포인터 이동·누름·해제를 보냈다. 1920×1080과 640×360에서 각각 20번의 입력을 끝까지 처리했다. 입력 좌표가 화면 안에 있는지도 확인했다.
- 기록표 열기, 초기화 확인 문구와 모드 선택 복귀, 한국어·일본어·영어 전환, 연습 진입, 조작표 열기·닫기, 시점 전환, 일시정지, 내부 관찰·갤러리 진입을 검사했다. 작은 화면용 임시 설정에서 1 BET을 Q로 변경하고 조작표에도 Q가 나오는지 검사했다. 실제 사용자 기록은 사용하지 않았다.
- 작은 창에서 펼친 조작표가 하단 버튼을 밀어내던 문제를 수정한 뒤 같은 입력을 재실행했다. 일본어 전환 시 발생하던 ICU 분절 모델 경고도 최종 두 실행에서 발생하지 않았다.
- Apple Silicon 릴리스 빌드와 ad-hoc 서명 검증 통과. 번들 실행 화면은 [메뉴](screenshots/menu_ui.png) · [플레이](screenshots/play_ui.png) · [일시정지](screenshots/pause_ui.png)에 있다. 포인터 입력 검증은 게임 내부 자동화이며 실제 트랙패드 제스처의 조작감은 별도 확인 대상이다.

## 화면 확인

앱 창이 다른 창에 가려지거나 화면이 잠겨 있으면 macOS가 창을 그리지 않아 스크린샷이 검게 나온다.
그래서 창 대신 화면 밖 이미지(1920×1080)에 그리는 `--offscreen` 옵션을 넣었고, 이것으로 다음을 확인했다.

- 플레이 시점: 배당표, 릴, 당첨 라인 막대와 양끝 등, 상태등, CREDIT·COUNT·PAYOUT, MAX BET·1 BET, 정지 버튼, 레버, 도어 키
- 전체·비스듬한 시점: 데이터 카운터(GAMES·BIG·REG·TOTAL)와 톱 램프, 받침

- 화면 UI: 메인 메뉴, HUD(모드·크레딧·베팅·지급, 연습 모드 힌트, 당첨 문구, 키 도움말), 일시정지·설정 화면

일시정지 패널이 너무 투명해 뒤의 게임기와 글자가 겹쳐 보이는 문제를 이 확인에서 발견해 고쳤다.
한국어 화면만 확인했다. 일본어·영어 화면은 보지 않았다.

iPhone 18 Pro 시뮬레이터(iOS 27.0)에서 시뮬레이터용 번들을 설치해 손가락 입력으로 확인했다.

- 일시정지·설정 화면, iPhone용 그래픽 설정 적용(MEDIUM)

## 테스트가 잡아낸 문제

개발 중 테스트로 발견해 고친 것들이다.

- 릴 제어가 포도·리플레이를 놓치는 경우가 있었다. 전수 검사로 발견했고, 첫 번째 정지에서 두 수 앞까지
  보는 보장 판정을 넣고 체리 규칙을 바꿔 해결했다.
- 일시정지 중에 들어온 조작이 일시정지를 푼 뒤에 뒤늦게 처리되었다. ECS 통합 테스트로 발견했다.
- 메달이 받침을 넘어 절반 가까이 밖으로 떨어졌다. 물리 테스트로 발견해 배출 속도와 자세를 조정했다.
- 2메달 게임에서 리플레이가 성립하지 못하는 누름 위치가 있었다. 유효 라인 수별 전수 검사로 발견해
  릴 배열을 교체했다.
- Classic 모드에서 메뉴로 나가거나 종료할 때 앱이 멈췄다. 세션 종료 잔액을 고치면서 저장소 잠금을 한 문장에서
  두 번 잡아 교착 상태가 된 것으로, 번들 실행 확인에서 종료하지 않는 것을 보고 발견했다. 고치고 회귀 테스트를
  추가했다. 이 버그는 약 15분 동안 작업 트리에 있었고 배포물로 나간 적은 없다.
- STAR CHANCE 램프가 릴이 멈추기 전(레버 시점)에 켜져 당첨이 미리 드러났다. 문서 검토 중 발견해 고치고
  테스트를 추가했다.
