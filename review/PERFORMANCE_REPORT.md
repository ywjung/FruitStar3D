# 성능 보고서

측정일: 2026-11-25 · 기기: Apple M4 Max (16코어, 128GB), macOS 27.2.1, 내장 120Hz 디스플레이
빌드: 릴리스(`lto = "thin"`, `codegen-units = 1`) · 품질 High · Bloom, 그림자, AO, 모션 블러, SMAA 켬 · 수직 동기화 켬

측정은 앱의 자동 플레이 옵션으로 했다 (`--auto-play --exit-after N`). 시작 후 2초는 통계에서 뺀다.
창은 3024×1718 물리 픽셀이다(설정은 1920×1080 논리 픽셀이지만 화면 크기에 맞춰 줄어든 결과).
계획서의 기준 해상도 1920×1080보다 픽셀 수가 약 2.5배 많은 조건이다.

## 2026-11-27 게임 음향

Apple M4 Max에서 새 릴리스 번들을 High 품질, 1920×1080 화면 밖 렌더링으로 16초 자동 플레이했다. 시작 2초를 제외한 1,931프레임은 평균 7.25 ms, 최대 13.54 ms였다. 시작 중에는 1,285 ms짜리 프레임이 기록됐다. 앱 전체의 프레임 측정이며 오디오 장치 지연이나 믹서 단독 CPU 사용률은 측정하지 않았다.

## 2026-11-27 릴 드럼

Apple M4 Max에서 arm64 릴리스 번들의 내부 관찰 확대 화면을 High 품질, 1920×1080 화면 밖 렌더링으로 측정했다. 시드 7과 메모리 저장소를 쓴 9초 자동 플레이에서 회전 화면 네 장을 캡처했다. 시작 2초를 제외한 885프레임에서 평균 7.92 ms, 최대 12.45 ms였다. 첫 번들 실행에서는 장면 준비 중 3.77초짜리 긴 프레임이 있었고, 6초 종료 예약으로는 캡처를 저장하지 못했다. 다음 실행에서 시간을 늘려 저장을 확인했다. 장시간 플레이와 다른 품질의 성능은 이번에 측정하지 않았다.

## 2026-11-26 UI 개편 후 번들 실행

Apple Silicon 릴리스 번들에서 High 품질, 1920×1080 화면 밖 렌더링으로 Free Play를 12초 자동 실행했다. 시드는 7, 저장소는 메모리이며 측정 중 스크린샷은 찍지 않았다. 앱의 기존 계측기가 시작 후 2초를 제외하고 집계한 601프레임에서 평균 16.67ms(60.0 FPS), 최대 22.19ms를 기록했다. 시작 직후에는 텍스처 가공 608ms와 668ms짜리 긴 프레임도 기록됐다. 이전 측정은 창 렌더링이어서 이번 수치로 UI 개편의 성능 차이를 산출할 수 없다. 이번 실행에서 메모리와 장시간 프레임률은 측정하지 않았다.

- 60 FPS 목표(16.67ms): 측정한 모든 실행에서 평균이 목표 안이다.
- 120 FPS 목표(8.33ms): 15초 이내 실행에서는 수직 동기화 한계인 120.0 FPS로 고정된다.
  **60초 실행에서는 평균 100.8 FPS로 떨어졌다.** 메달이 상한(60장)까지 쌓인 뒤의 물리·충돌 처리 비용으로
  추정하지만 프로파일링으로 확인하지 않았다. 원인 분석이 필요하다.
- 120 FPS를 넘는 여유가 얼마인지는 알 수 없다. 수직 동기화를 끈 측정을 하지 않았다.

## 멈춤

| 상황 | 길이 | 내용 |
|---|---:|---|
| 새 바이너리의 첫 실행 | 3.6초, 2.2초, 1.1초 | 플레이 시작 직후 세 번. 같은 바이너리를 다시 실행하면 사라진다. Metal 셰이더 캐시가 비어 있을 때의 파이프라인 컴파일로 판단한다(재실행 시 사라지는 것 외의 직접 증거는 없음) |
| 매 실행, 장면 준비 | 약 0.7초 | 로딩 직후 한 프레임 |
| 로딩 중 텍스처 가공 | 0.6초 (디버그 0.9초) | 릴 띠 합성과 밉맵 생성. 메인 스레드 |
| 스크린샷 옵션 사용 시 | 측정 안 함 | 처음에는 3초 멈춤의 원인으로 보았으나, 위 첫 실행 멈춤과 겹친 것일 수 있어 따로 재지 않았다 |

## 메모리 (60초 실행, `/usr/bin/time -l`)

| 항목 | 값 | 목표 |
|---|---:|---|
| 최대 상주 메모리 (RSS) | 617 MB | 2GB 이하 |
| 최대 메모리 footprint | 1,833 MB | 2GB 이하 |

footprint 기준으로는 목표에 가깝다. Ultra 품질(릴 띠 1024×8694 텍스처 3장)에서는 재지 않았다.

CPU 시간은 60초 실행에 user 55초, sys 55초였다. 여러 코어 합계이며 코어별 분석은 하지 않았다.

## 도메인 로직 (Criterion, `cargo bench -p fruit-star-game`)

| 항목 | 시간 |
|---|---:|
| 조합 평가 (유효 라인 5개) | 18.3 ns |
| 릴 한 개의 한 프레임 갱신 | 9.9 ns |
| 정지 위치 결정: 첫 번째 릴 (두 수 앞 판정) | 257.7 µs |
| 정지 위치 결정: 두 번째 릴 | 8.7 µs |
| 정지 위치 결정: 마지막 릴 | 67.3 ns |
| 한 게임 전체 (베팅 → 정지 → 정산) | 90.1 µs |

가장 무거운 첫 번째 정지 판정도 0.26ms로 120 FPS 프레임 예산(8.33ms)의 약 3%이며 버튼을 누른 프레임에만 실행된다.

## 하지 않은 것

- 24시간 안정성 시험
- Instruments, Metal 프로파일러를 이용한 실측과 발열 확인
- Low / Medium / Ultra 품질별 측정, 1920×1080 창 크기에서의 측정
- 수직 동기화를 끈 상태의 최대 프레임률, `target_fps` 제한 동작 확인
- M4 Max보다 낮은 사양의 Apple Silicon 기기에서의 측정

## 11월 27일 재측정 (화면 밖 렌더링 1920×1080, 릴리스, 60초, 자동 플레이)

| 조건 | 평균 | 최대 |
|---|---:|---:|
| 메달 연출 켬 | 8.68 ~ 8.96 ms (111.6 ~ 115.2 FPS) | 16.6 ~ 18.4 ms |
| 메달 연출 끔 (`max_medals = 0`) | 8.72 ~ 8.75 ms (114.2 ~ 114.7 FPS) | 16.9 ~ 17.1 ms |

- 이전에 기록한 "60초 실행에서 100.8 FPS로 저하"는 이번 빌드에서 재현되지 않았다. 메달 물리는 원인이 아니었다.
- 프레임 제한기를 기준 시각 누적 방식으로 바꿨지만(테스트 있음), 측정상 개선은 없었다. 평균 8.7ms는 제한기보다
  렌더링 작업에 묶인 값으로 보인다.
- 같은 조건의 반복 측정이 69 ~ 115 FPS로 크게 흔들린 경우가 있었다. 앱 창이 다른 창 뒤에 있을 때 macOS가 백그라운드
  앱의 타이머를 늦추는 영향으로 판단하며, 이 환경에서는 정밀한 비교를 할 수 없었다.
- 새로 빌드한 실행 파일의 첫 실행에서 최대 1.3초 멈춤이 다시 관찰됐다 (셰이더 컴파일). → 같은 날 렌더 예열로
  로딩 화면 안으로 옮겼다. 예열 약 300 ms·7프레임, 이후 12초 플레이에서 새 파이프라인 0개, 최대 16.2 ms.
