# USER_GUIDE

FRUIT STAR 3D를 실행하고 플레이하는 방법이다. 이 프로그램은 가상 메달만 사용한다.
메달에는 금전적 가치가 없고 결제·환전·네트워크 기능이 없다.

## 1. 실행

```bash
cargo run --release -p fruit-star-app      # 또는 scripts/run.sh
```

- macOS(Apple Silicon)가 필요하다. Rust 툴체인은 처음 빌드할 때 자동으로 설치된다 ([README](../README.md)).
- 프로그램은 `assets/`와 `config/`가 함께 있는 디렉터리를 찾아 리소스 루트로 쓴다. 워크스페이스 밖에서
  실행 파일만 따로 실행할 때는 환경 변수 `FRUIT_STAR_ROOT`에 그 디렉터리를 지정한다.
- "실행할 수 없습니다" 화면이 나오면 화면에 적힌 파일이 없는 것이다.
  `cargo run -p fruit-star-assetgen --release`로 그림과 효과음을 다시 만든다.

## 2. 메인 메뉴

| 항목 | 내용 |
|---|---|
| Classic 플레이 | 보유 메달로 플레이한다. 메달은 다음 실행까지 유지된다 |
| Free Play | 메달이 모자라면 자동으로 채워진다 |
| Practice (연습) | Free Play와 같고, 화면에 이번 게임의 내부 추첨 결과가 표시된다 |
| Mechanical View (내부 관찰) | 외장을 숨긴 채 Free Play로 플레이한다 |
| Gallery (둘러보기) | 조작 없이 게임기를 둘러본다 |
| 언어 | 한국어 / 일본어 / 영어 |
| 기록 초기화 | 두 번 눌러 확인한다 (7절) |
| 종료 | 프로그램을 끝낸다 |

메뉴 아래의 **플레이 기록**을 열면 플레이 횟수, 투입·지급, 보너스 횟수, 플레이 시간, 달성 개수를 볼 수 있다. **모드 선택**으로 돌아간다.

## 3. 플레이 방법

한 게임은 **베팅 → 레버 → 정지 세 번** 순서다. 게임기의 표시등이 누를 수 있는 버튼을 알려 준다. 왼쪽 아래 **조작표 열기**를 누르면 현재 설정된 단축키를 볼 수 있다.

1. **메달 확인.** Classic은 처음에 50장으로 시작한다. 모자라면 `C`를 눌러 50장을 추가한다 (최대 9999장).
2. **베팅.** `B`(MAX BET)를 누르면 3장을 한 번에 건다. `N`(1 BET)은 한 장씩 걸며 최대 3장까지다.
   건 메달 수에 따라 유효 라인이 달라진다: 1장은 가운데 한 줄, 2장은 가로 세 줄, 3장은 대각선을 포함한
   다섯 줄이다. 표시창 양옆의 작은 등이 지금 유효한 줄을 보여 준다. 당첨 확률은 건 메달 수에 비례하고
   배당은 같으므로, 적게 걸면 천천히 플레이하는 것일 뿐 유불리는 없다.
3. **레버.** `Space`로 START 레버를 당기면 릴 세 개가 돈다.
4. **정지.** 릴이 정속에 이르면 정지 버튼에 불이 들어온다. `1` `2` `3`(또는 `A` `S` `D`)으로 왼쪽·가운데·오른쪽
   릴을 원하는 순서로 멈춘다. 릴은 누른 위치에서 최대 4칸까지 미끄러진 뒤 멈춘다.
5. **결과.** 세 릴이 멈추면 조합을 평가하고 메달을 지급한다. 지급되는 동안 PAYOUT 표시기가 올라가고
   받침으로 메달이 떨어진다. 지급이 끝나면 다음 게임을 할 수 있다.

받을 수 없는 시점의 입력(회전 중 베팅, 같은 릴을 두 번 정지, 베팅 없이 레버 등)은 버튼이 눌리는 모습과
소리만 나고 아무 일도 일어나지 않는다.

### 배당

가로 세 줄과 대각선 두 줄, 모두 5개 라인 가운데 하나에 같은 그림 세 개가 늘어서면 성립한다.

| 조합 | 결과 |
|---|---|
| 스타 × 3 | 15장 |
| 수박 × 3 | 12장 |
| 벨 × 3 | 10장 |
| 포도 × 3 | 8장 |
| 체리 × 3 | 4장 |
| REPLAY × 3 | 다음 게임 무료 (베팅이 자동으로 놓인다. 레버만 당기면 된다) |
| 빨간 7 × 3, 파란 7 × 3 | BIG 보너스 시작 |
| BAR × 3 | REGULAR 보너스 시작 |

한 게임의 지급은 최대 15장이다. 확률을 포함한 자세한 규칙은 [GAME_DESIGN.md](GAME_DESIGN.md)에 있다.

### 보너스와 STAR CHANCE

- 표시창 왼쪽의 **STAR CHANCE** 램프가 켜지면 보너스가 대기 중이라는 뜻이다. 대기 중인 보너스가 BIG이면
  같은 색 7 세 개, REGULAR이면 BAR 세 개를 한 줄에 맞춰야 시작된다. 램프만으로는 어느 쪽인지 알 수 없다
  (Practice 모드에서는 화면에 표시된다). 맞출 때까지 램프는 꺼지지 않는다.
- 램프는 당첨된 게임의 약 1/4에서 레버를 당기는 순간 켜진다. 이때는 그 게임에서 바로 7을 노려 볼 수 있다.
  나머지는 릴이 모두 멈춘 뒤에 켜진다.
- 보너스 중에는 포도가 높은 확률로 나온다. 매 게임 베팅(3장)은 그대로 한다.
- 보너스 중 받은 메달이 BIG은 240장, REGULAR는 96장에 이르면 끝난다. COUNT 표시기가 남은 장수를 보여 준다.
- 진행 중인 보너스와 대기 중인 보너스는 저장되지 않는다. 메뉴로 나가면 사라진다.

### 캐비닛 표시기

| 표시 | 의미 |
|---|---|
| CREDIT | 보유 메달 |
| COUNT | 보너스 중 남은 지급 장수 (보너스가 아니면 꺼짐) |
| PAYOUT | 이번 게임에서 지급된 장수 |

## 4. 조작

### 키보드 (기본값)

| 키 | 기능 | 쓸 수 있는 곳 |
|---|---|---|
| `B` | MAX BET (3장까지 한 번에) | 플레이 중 |
| `N` | 1 BET (한 장씩) | 플레이 중 |
| `Space` | START 레버 | 플레이 중 |
| `1` `2` `3` / `A` `S` `D` | 왼쪽 / 가운데 / 오른쪽 릴 정지 | 플레이 중 |
| `C` | 가상 메달 50장 추가 | 플레이 중 |
| `V` | 카메라 프리셋 전환 | 게임기 앞 |
| `P`, `Esc` | 일시정지 · 설정 화면 열기 / 닫기 | 게임기 앞 |
| `F` | 전체 화면 전환 | 어디서나 |
| `M` | 음소거 전환 | 어디서나 |
| `F3` | 디버그 표시 | 개발 빌드에서만 |

키 배정은 `config/controls.toml`의 `[keys]`에서 바꾼다. 키 이름은 `KeyA`, `Digit1`, `Space`, `Escape`, `F3` 같은
표기를 쓰고, 한 키를 두 동작에 배정할 수 없다.

### 마우스 · 트랙패드

| 동작 | 기능 |
|---|---|
| 레버 손잡이 클릭 | START 레버 |
| MAX BET / 1 BET 버튼 클릭 | 베팅 |
| 정지 버튼 클릭, 또는 릴 자체를 클릭 | 그 릴 정지 |
| 메달 투입구 클릭 | 메달 추가 |
| 빈 곳을 누른 채 끌기, 오른쪽 버튼으로 끌기 | 카메라 회전 |
| 스크롤, 트랙패드 핀치 | 확대 · 축소 |

부품을 누른 채 끄는 동작으로는 카메라가 돌지 않는다. 회전·확대 감도는 `config/controls.toml`의 `[mouse]`에 있다.

### 카메라

`V`를 누를 때마다 보기 방식별 프리셋이 바뀐다. Play는 플레이 시점(릴과 조작부가 화면을 채움) → 게임기 전체(위의 데이터 카운터까지) → 왼쪽 → 오른쪽 → 릴 확대, Mechanical은
좌우 비스듬한 시점 → 릴 유닛 확대 → 위에서 본 시점, Gallery는 자동 회전 → 왼쪽 → 오른쪽 순이다.
직접 끌거나 확대하면 그 자리에서 자유롭게 볼 수 있다.

## 5. 일시정지와 설정

오른쪽 아래 **일시정지**를 클릭하거나 `P`, `Esc`를 누르면 게임이 멈추고 음향·화면 설정판이 열린다.

| 항목 | 설명 |
|---|---|
| 전체 음량 / 효과음 / 배경음 | 10% 단위로 조절 |
| LED 밝기 | 0 ~ 150% |
| 점멸 줄이기 | 깜빡이는 조명 연출을 느리고 완만한 밝기 변화로 바꾼다. 빛에 민감하면 켜 둔다 |
| 그래픽 품질 | LOW / MEDIUM / HIGH / ULTRA. **재시작 후** 적용된다 |
| 언어 | 한국어 / 일본어 / 영어 |
| 계속하기 / 메뉴로 | 게임으로 돌아가기 / 메인 메뉴로 나가기 |

게임 도중에 메뉴로 나가면 진행 중이던 게임은 기록되지 않는다.

## 6. 설정 파일

`config/` 아래의 TOML 파일을 고치면 다음 실행부터 적용된다. 각 키의 설명과 허용 범위는 파일 안의 주석에 있다.

| 파일 | 내용 |
|---|---|
| `application.toml` | 창 크기, 전체 화면, vsync, 시작 언어, 첫 실행 메달 수, 메달 추가량 |
| `graphics.toml` | 품질, 목표 프레임률, Bloom·그림자·AO·모션 블러, 메달 수 상한, LED, 카메라 |
| `audio.toml` | 음량, 음소거, 공간 음향 |
| `controls.toml` | 키 배정, 마우스 감도 |
| `machines/fruit_classic.toml` | 릴 배열, 배당, 추첨표, 타이밍 |

알아 둘 점:

- 파일이 없거나 값이 범위를 벗어나면 그 파일 전체를 기본값으로 대체하고 로그에 경고를 남긴다.
- 화면에서 바꾼 설정(언어, 음량 3종, 음소거, 그래픽 품질, LED 밝기, 점멸 줄이기)은 기록 파일에 저장되고,
  다음 실행 때 **TOML 값보다 우선한다.** 이 항목들을 TOML로 되돌리려면 화면에서 다시 맞추거나 기록 파일을 지운다.
- `graphics.toml`의 `render_scale`은 현재 화면에 반영되지 않는다.

## 7. 기록

| 항목 | 내용 |
|---|---|
| 위치 | `~/Library/Application Support/FruitStar3D/fruitstar.sqlite3` (SQLite) |
| 저장되는 것 | 게임별 결과와 릴 정지 위치, 메달 투입·베팅·지급 내역, 플레이 세션, Classic 보유 메달, 달성 기록, 화면에서 바꾼 설정 |
| 저장되지 않는 것 | 대기 중·진행 중인 보너스, 리플레이 대기, 끝나지 않은 게임 |

- **기록 초기화**: 메인 메뉴의 **플레이 기록** 안에서 "기록 초기화"를 누르고, 문구가 바뀐 뒤 4초 안에 한 번 더 누른다.
  플레이 기록, 통계, 달성 기록, Classic 보유 메달이 지워진다. 화면에서 바꾼 설정은 남는다.
  되돌릴 수 없다. 초기화 뒤 Classic은 다시 50장으로 시작한다.
- **전부 지우기**: 프로그램을 끝낸 뒤 위 디렉터리의 `fruitstar.sqlite3`와 같은 이름으로 시작하는
  `-wal`, `-shm` 파일을 지운다. 다음 실행 때 새로 만들어진다.
- **다른 위치 사용**: `--db <경로>`로 다른 파일을 쓰거나 `--db :memory:`로 저장 없이 실행한다.
- 기록 파일을 열 수 없으면 그 실행은 메모리에만 기록하고, 메뉴에서 이번 실행의 기록만 표시한다는 문구를 볼 수 있다.
- 프로그램이 비정상 종료되어도 완료된 게임의 기록은 남는다. 다음 실행 때 닫히지 않은 세션을 정리하고,
  보유 메달 값이 원장 기록과 다르면 원장 기준으로 바로잡는다.

통계와 기록은 열람과 검증용이다. 결과를 예측하는 기능은 없다.

## 8. 명령줄 옵션

```text
--mode <classic|free_play|practice>   메뉴를 건너뛰고 바로 시작
--view <play|mechanical|gallery>      보기 방식 (--mode와 함께)
--seed <숫자>                          난수 시드 고정
--db <경로|:memory:>                   데이터베이스 위치
--help                                도움말
```

`--auto-play`, `--screenshot`, `--camera-at`, `--exit-after`는 자동 실행 확인용이다 ([TEST_PLAN.md](TEST_PLAN.md) 4절).

## 9. 알려진 제약

- 기종은 FRUIT CLASSIC 한 대뿐이다.
- 효과음은 모두 코드로 합성한 것이며 사람이 들어 보고 조정하지 않았다.
- 캐비닛은 기본 도형으로 조립한 모델이다.
- 그래픽 품질은 재시작해야 바뀌고, `render_scale`은 동작하지 않는다.
- 전체 화면 상태는 저장되지 않는다. 항상 전체 화면으로 시작하려면 `application.toml`의 `window.fullscreen`을 `true`로 둔다.
- 디버그 표시(`F3`)는 개발 빌드(`cargo run`, `--release` 없이)에서만 동작한다.
