# GAME_DESIGN

FRUIT CLASSIC 기종의 규칙을 코드와 설정 기준으로 정리한다. 수치는 모두
[config/machines/fruit_classic.toml](../config/machines/fruit_classic.toml)에서 온 것이며, 같은 값이
`MachineProfile::fruit_classic()`에 내장되어 있다 (두 값의 일치는 `config/tests/config.rs`가 검사한다).

규칙·확률·배당은 이 프로젝트가 독자적으로 정했다. 메달은 가상이며 금전적 가치가 없다.

## 1. 구성

| 항목 | 값 | 출처 |
|---|---|---|
| 릴 | 3개, 릴당 21심볼, 표시창 3줄 | `[reel]` |
| 베팅 | 게임당 1~3메달. MAX BET은 3메달까지 한 번에, 1 BET은 한 장씩 | `rules.bet`(최대 베팅) |
| 유효 라인 | 1메달 = 가운데 1줄, 2메달 = 가로 3줄, 3메달 = 가로 3줄 + 대각선 2줄 | `evaluator::active_lines` |
| 당첨 확률 | 베팅 수에 비례 (추첨표는 3메달 기준). 배당은 베팅 수와 무관 | `LotteryTable::draw_for_bet` |
| 게임당 최대 지급 | 15메달 | `rules.max_payout` |
| 최대 미끄러짐 | 4칸 | `reel.max_slip` |
| 유효 라인 | 5개: 가운데, 위, 아래, 대각선 2개 | `evaluator.rs`의 `PAYLINES` |

릴 세 개의 심볼 구성은 같다: 포도 5, REPLAY 5, 체리 2, 벨 2, 수박 2, 스타 2, 빨간 7 1, 파란 7 1, BAR 1.
배열 순서는 릴마다 다르다. 인덱스가 커질수록 릴 표면의 위쪽이고, 정지 위치가 `i`이면 표시창은
위에서부터 `i+1`, `i`, `i−1`번 심볼을 보여 준다.

## 2. 역할과 배당

모든 역할은 유효 라인 하나에 같은 심볼 세 개가 늘어서는 것이다 (체리 포함).

| 역할 (`Role`) | 심볼 | 지급 | 효과 |
|---|---|---:|---|
| `replay` | REPLAY × 3 | 0 | 다음 게임을 메달 차감 없이 진행 |
| `grape` | 포도 × 3 | 8 | |
| `cherry` | 체리 × 3 | 4 | |
| `bell` | 벨 × 3 | 10 | |
| `melon` | 수박 × 3 | 12 | |
| `star` | 스타 × 3 | 15 | |
| `big_red` / `big_blue` | 빨간 7 × 3 / 파란 7 × 3 | 0 | BIG 보너스 시작 |
| `regular_bar` | BAR × 3 | 0 | REGULAR 보너스 시작 |

여러 라인에 동시에 성립하면 합산하되 게임당 15메달을 넘지 않는다.

## 3. 내부 추첨

레버를 당기는 순간 `0..65536` 범위의 난수 하나로 이번 게임에 성립이 허용되는 역할(`Flag`)을 정한다.
가중치 합의 나머지는 꽝이다.

| 일반 게임 (`lottery.normal`) | 가중치 | 확률 |
|---|---:|---:|
| `replay` | 8978 | 13.70% |
| `grape` | 11200 | 17.09% |
| `cherry` | 1820 | 2.78% |
| `bell` | 655 | 1.00% |
| `melon` | 546 | 0.83% |
| `star` | 164 | 0.25% |
| `big` (빨간 7 또는 파란 7) | 280 | 0.43% |
| `regular` (BAR) | 172 | 0.26% |
| 꽝 | 41721 | 63.66% |

| 보너스 게임 (`lottery.bonus`) | 가중치 | 확률 |
|---|---:|---:|
| `grape` | 60000 | 91.55% |
| 꽝 | 5536 | 8.45% |

- 소역(`Flag::Small`)은 그 게임에서만 유효하다. 맞추지 못하면 사라진다.
- 보너스(`Flag::Bonus`)는 조합을 맞출 때까지 다음 게임으로 이월된다 (`carried_bonus`).
  이월 중이거나 보너스 진행 중에 다시 뽑힌 보너스는 꽝으로 처리한다.

## 4. 한 게임의 흐름

```text
베팅 → 레버(추첨) → 릴 3개 회전 → 정지 버튼 3회(릴 제어) → 세 릴 정지 → 평가·정산 → 결과 표시 → 대기
Phase:  Ready ─────────→ Spinning ─────→ Stopping ───────────→ Evaluating → Result ────→ Ready
```

1. **추첨** (`lottery.rs`): 위 표로 `Flag`를 뽑고, 이월 보너스와 합쳐 허용 역할(`Allowed`)을 만든다.
2. **릴 제어** (`control.rs`): 정지 버튼을 누르면, 다음에 가운데 줄에 올 심볼 인덱스(`Reel::next_index`)를
   누른 위치로 보고 거기서 0~4칸 미끄러진 후보 가운데 하나를 고른다. 선택 기준은 순서대로 다음과 같다.
   1. 허용되지 않은 역할이 성립하는 위치는 제외한다.
   2. 마지막 릴이 어디서 눌려도 합법적인 정지 위치가 남는 후보를 우선한다.
   3. 릴이 두 개 남았을 때, 당첨된 소역의 성립이 보장되는 후보를 우선한다.
   4. 당첨된 소역이 성립할 여지가 큰 후보를 우선한다 (한 릴이 남았으면 성립시킬 수 있는 누름 위치의 수,
      그 밖에는 성립 가능한 라인이 남아 있는지 여부).
   5. 허용된 보너스 조합에 대해 같은 점수를 매겨 우선한다. 소역이 보너스보다 앞선다.
   6. 나머지는 가장 적게 미끄러지는 후보를 고른다.

   결과는 누른 위치, 이미 멈춘 릴, 허용 역할에 대해 결정적이다. 난수를 쓰지 않는다.
3. **평가** (`evaluator.rs`): 세 릴이 모두 `Stopped`가 되면 릴의 실제 정지 인덱스로 표시창 심볼을 구하고,
   그 심볼만으로 성립 역할과 지급을 계산한다. 추첨 결과는 평가에 쓰이지 않는다.
4. **정산**: `CreditLedger::settle`로 지급하고 `GameCompleted`를 한 번 낸다.
   결과 단계는 `250 ms + 지급 메달 수 × 70 ms` 동안 유지된다 (`[flow]`). 화면의 메달 배출 연출과 CREDIT
   표시는 이 간격으로 한 장씩 따라간다. 원장은 정산 시점에 이미 반영되어 있다.

### 보장되는 성질

| 성질 | 근거 |
|---|---|
| 표시된 심볼과 내부 결과가 항상 같다 | 평가 입력이 릴의 정지 인덱스뿐이다. `controller.rs`의 `displayed_symbols_match_the_internal_result` |
| 허용되지 않은 역할은 성립하지 않고, 미끄러짐은 4칸을 넘지 않는다 | 모든 허용 조합 × 정지 순서 6가지 × 누름 위치 21³을 전수 검사 (`rules.rs`의 `reel_control_never_produces_a_disallowed_win`) |
| 포도와 REPLAY는 당첨되면 어디서 어떤 순서로 눌러도 성립한다 | `rules.rs`의 `grape_and_replay_are_always_pulled_in`, 예제 `strip_search` |
| 7과 BAR는 정확히 노리면 맞출 수 있다 | `rules.rs`의 `bonus_symbols_can_be_aligned_when_aimed` |
| 정산은 게임당 한 번이다 | `settle_game`이 진행 중 게임을 `take()`하고, 원장이 같은 게임 ID의 재정산을 거부한다 |

체리, 벨, 수박, 스타는 릴당 2개뿐이라 누른 위치에 따라 놓칠 수 있다. 이 역할들에 대한 성립 보장은 없다.

릴 배열을 바꾼 뒤에는 `cargo run --release -p fruit-star-game --example strip_search`로 위 조건을 다시 검증한다.

### 베팅 수와 유효 라인

1 BET 버튼으로 1~3메달을 걸 수 있다. 유효 라인은 `PAYLINES`의 앞에서부터 1, 3, 5줄이 된다. 유효하지 않은
라인에 같은 심볼이 늘어서도 당첨이 아니며, 릴 제어도 유효 라인만 본다. 당첨 확률은 베팅 수에 비례하도록
추첨 범위를 `최대 베팅 ÷ 베팅 수`배로 넓힌다. 배당은 같으므로 메달당 기대 환수는 베팅 수와 무관하다.
릴 제어의 두 보장(허용되지 않은 역할 불성립, 포도·리플레이 항상 성립)은 1·3·5줄 모두에서 전수 검사한다
(`tests/rules.rs`, `examples/strip_search.rs`). 리플레이는 성립한 게임과 같은 메달 수로 무료 진행된다.

## 5. 리플레이

REPLAY가 성립하면 결과 표시가 끝날 때 베팅이 자동으로 놓인다 (`BetPressed { replay: true }`).
원장에서 메달을 차감하지 않으며, 그 게임의 기록에는 베팅 원장 항목이 없다 (`replay_game = true`).

## 6. 보너스

| 항목 | BIG | REGULAR |
|---|---|---|
| 시작 조합 | 빨간 7 × 3 또는 파란 7 × 3 | BAR × 3 |
| 종료 조건 | 보너스 중 누적 지급 ≥ 240 | 누적 지급 ≥ 96 |
| 보너스 중 추첨 | `lottery.bonus` | `lottery.bonus` |

- 보너스 게임도 매 게임 3메달을 베팅한다. 시작 조합이 성립한 게임 자체는 보너스 게임 수에 포함되지 않는다.
- 종료 판정은 매 게임 정산 직후에 한다. 한도에 도달한 게임에서 `BonusCompleted { kind, paid, games }`가 난다.
- COUNT 표시기는 보너스 중에만 켜지고 남은 지급 가능 메달 수(`payout_cap − paid`)를 보여 준다.
- **STAR CHANCE 램프**: 보너스 당첨을 두 가지 시점으로 알린다 (`GameController::chance_lamp()`,
  `ChanceLampChanged(true)` 이벤트와 효과음 `chance_lamp`가 함께 난다).
  - **선고지**: 당첨 게임 중 `bonus.lamp_lead_percent`(기본 25%)는 레버를 당기는 순간, 릴이 돌기 전에 켜진다.
    이 게임에서 7(또는 BAR)을 노려 바로 맞출 수 있다. 맞추면 램프가 꺼지고 보너스가 시작된다.
  - **후고지**: 나머지는 릴이 모두 멈추고 조합을 맞추지 못한 것이 확인될 때 켜진다. 이 경우 당첨된 게임에서
    우연히 조합이 맞으면 램프는 켜지지 않는다.
  - 선고지로 켜진 램프는 게임이 끝나도 다시 켜지지 않는다(효과음은 한 번). 이월 중에 조합을 맞추면 꺼진다.
  - 일본 실기의 고지 램프(선고지 약 1/4, 셋째 정지 후 후고지 약 3/4)를 참고한 비율이다. 실기의 램프 이름·그림은 쓰지 않는다.

## 7. 모드

플레이 모드(`PlayMode`)와 보기 방식(`ViewMode`)은 서로 독립된 값이다.

| 플레이 모드 | 시작 메달 | 메달 부족 시 | 그 밖 |
|---|---|---|---|
| Classic | 저장된 보유 메달. 기록이 없으면 `initial_credit`(50) | 베팅 거부. `C`로 50장씩 추가 (상한 `credit_limit` 9999) | 보유 메달이 실행 사이에 유지된다 |
| Free Play | 0 | 베팅 시 자동으로 50장 충전 | Classic 보유 메달을 건드리지 않는다 |
| Practice | 0 | Free Play와 같음 | HUD에 이번 게임의 내부 추첨 결과와 이월 보너스를 표시한다 |

| 보기 방식 | 조작 | 내용 |
|---|---|---|
| Play | 가능 | 정면에서 플레이 |
| Mechanical | 가능 | 외장을 숨기고 내부 구조를 보면서 플레이 |
| Gallery | 불가 | 게임기 조작 명령을 받지 않는다. 카메라만 움직인다 |

메인 메뉴의 Mechanical View와 Gallery 항목은 Free Play 모드로 시작한다. 다른 조합은 명령줄
옵션(`--mode`, `--view`)으로만 만들 수 있다.

## 8. 릴 상태와 타이밍

릴 위치는 "스텝"(심볼 한 칸) 단위의 연속 값이며, 모든 갱신은 경과 시간에 대한 구간별 해석적 적분이라
프레임률과 무관하게 같은 결과를 낸다 (`core/tests/reel.rs`의 `result_is_independent_of_frame_rate`).

| 상태 | 동작 | 설정 |
|---|---|---|
| `Idle` | 전원 투입 후 아직 돌지 않음 | |
| `Accelerating` | 등가속으로 정속까지 | `acceleration_ms = 350` |
| `Spinning` | 정속 회전. 이 상태에서만 정지 입력을 받는다 | `spin_rpm = 80` (초당 28칸) |
| `Decelerating` | 목표까지 정속으로 가다가 제동 구간에서 등감속 | `deceleration_ms = 250` (기준 제동 거리 3.5칸. 목표가 더 가까우면 더 짧게 멈춘다) |
| `Settling` | 목표 위치에 고정된 뒤 표시용 감쇠 진동. 논리 위치는 변하지 않는다 | `settling_ms = 80`, 진폭 최대 0.07칸 |
| `Stopped` | 완전 정지 | |

`ReelStopped` 이벤트는 `Settling`에 들어가는 순간(정지음이 나는 시점)에 나고, 평가는 세 릴이 모두
`Stopped`가 된 뒤에 한다. 조작부 애니메이션 시간은 `[animation]`에 있다: 레버 250 ms, 정지 버튼 120 ms,
MAX BET 100 ms, 메달 투입 400 ms.

## 9. 받아들이지 않는 입력

도메인은 받을 수 없는 입력을 오류(`GameError`)로 거부하고 상태를 바꾸지 않는다.

| 입력 | 상황 | 오류 |
|---|---|---|
| 베팅 | 회전 중·정지 중·결과 표시 중 | `WrongPhase` |
| 베팅 | 이미 베팅됨 (리플레이 자동 베팅 포함) | `AlreadyBet` |
| 베팅 | Classic에서 메달 부족 | `Credit(Insufficient)` |
| 레버 | 베팅 없음 | `BetRequired` |
| 레버 | 게임 진행 중 | `WrongPhase` |
| 정지 | 릴이 아직 정속이 아님, 또는 이미 정지 입력을 받은 릴 | `StopNotReady` |
| 정지 | 없는 릴 번호 | `InvalidReel` |
| 메달 투입 | 상한 초과 | `Credit(LimitExceeded)` |

ECS 계층(`machine/plugin.rs`의 `apply_commands`)에서의 처리:

- 거부된 입력도 `PartPressed { accepted: false }`를 낸다. 버튼은 눌리고 소리도 나지만 게임 상태는 그대로다.
- 일시정지 중이거나 게임기 앞이 아닐 때 들어온 명령은 버린다. 나중에 뒤늦게 처리되지 않는다.
- Gallery에서는 명령을 건너뛴다.
- 메달 투입은 게임 진행 단계와 무관하게 받는다.

## 10. 메달 원장의 불변식 (`core/credit.rs`)

- 잔액은 `insert`, `bet`, `settle` 세 연산으로만 바뀐다. 호출하는 곳은 `GameController`뿐이다.
- 잔액은 `u32`이고, 잔액보다 큰 베팅은 거부되므로 음수가 될 수 없다.
- 덧셈은 넘침을 검사한다. 오류가 나면 잔액과 누계는 바뀌지 않는다.
- `settle(game_id, …)`은 마지막으로 정산한 게임 ID보다 큰 ID만 받는다. 지급이 0이어도 정산 완료로 표시한다.
- 투입 상한(`insert_limit`)은 투입에만 적용된다. 지급으로는 상한을 넘을 수 있다.
- 모든 변경은 일련번호가 붙은 `LedgerEntry`(종류, 금액, 변경 후 잔액)로 남고, 저장 계층이 그대로 기록한다.
- 장기 시뮬레이션(`game/tests/simulation.rs`)이 매 게임 `잔액 = 투입 + 지급 − 베팅`과
  "지급 = 표시 심볼의 재평가 결과"를 확인한다. 같은 테스트가 환수율이 정해진 범위 안인지도 본다
  (무작위 누름 45%~100%, 노려 누름 80%~110%. 실제 측정값은 `review/TEST_RESULT.md`에 기록한다).

## 11. 미구현 / 계획과의 차이

- 기종은 FRUIT CLASSIC 한 대다. GOLD SEVEN, TOKYO NEON, RETRO 1970은 시작하지 않았다.
- 이월 보너스, 진행 중인 보너스, 대기 중인 리플레이는 저장하지 않는다. 메뉴로 나가거나 종료하면 사라진다.
- 게임 도중 메뉴로 나가거나 종료하면 그 게임은 기록되지 않는다. Classic의 저장된 보유 메달은 마지막으로
  완료된 게임(또는 투입) 시점의 값이므로, 다시 시작하면 끝내지 못한 게임의 베팅은 차감되지 않은 상태다.
- Practice 모드의 추첨 결과 지정 기능(`GameController::set_forced_flag`)은 도메인과 테스트에만 있고
  화면에서 쓸 방법이 없다.
- 플레이 중 모드 전환(`set_mode`)은 화면에 없다. 모드를 바꾸려면 메뉴로 돌아가 새로 시작한다.
- 통계는 모드를 구분하지 않고 모든 게임을 합산한다.
